# Printmn Web

`printmn-expo` (Konica Minolta native app)-ийн дизайн систем дээр суурилсан
маркетинг + онлайн захиалгын вэбсайт.

## Ажиллуулах

```bash
npm install
npm run dev        # http://localhost:5173 (API-гүй — доорх тайлбарыг үз)
npm run build      # tsc -b && vite build → dist/
npm run verify     # typecheck + test + docs:check
npm run lint
```

Систем бүтэц, захиалгын урсгал, `/pmn` ERD → [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

`/api/order`-ыг локалд ажиллуулахын тулд `vercel dev` хэрэглэнэ (`npm i -g vercel`),
эсвэл `.env` дотор `RTDB_AUTH`-ыг тавиад deploy хийгээд шалгана. `vite dev` дангаараа
static файл л үйлчилдэг тул захиалга илгээхэд 404 өгнө.

### `/hevlel` — хэвлэлийн урсгал

1. **Таб** — Угаалт / Засвар / Фото цаас (каталогийн категориуд).
2. **Хэмжээний карт** — `lib/photoSize.ts` нь үйлчилгээний нэрнээс (`10*15`,
   `А4`) хэмжээг таньж, зөв харьцаатай preview, 300dpi-ийн санал болгох
   нягтрал, үнэ, бэлэн болох хугацааг харуулна.
3. **Зураг сонгох** — карт дээр дарахад `PhotoEditor` нээгдэж зураг оруулах,
   хэдэн ширхэг хэвлэхээ сонгоно. **Засварын хэрэгсэл байхгүй** — зураг цаасны
   харьцаанд төвөөрөө автоматаар багтана (`lib/photoRender.ts`), preview дээр
   харагдаж буй зүйл хэвлэгдэх файлтай яг ижил. Нягтрал багавтар байвал
   анхааруулга гарна.
4. **Сагс** — `state/basket.tsx` контекст. Хуудас хооронд хадгалагдана.
5. **Захиалга илгээх** — `/zakhialga` дээр зураг эхлээд R2 руу байршиж, дараа
   нь захиалга Firebase рүү бичигдэнэ ("Зураг хүлээн авах" хэсгийг үз).

Тайралт нь чухал хэсгийг таслах эрсдэлтэй тул **эх файлыг мөн хамт** хадгалдаг
— ажилтан шаардлагатай бол тэндээс дахин бэлдэнэ.

Захиалга илгээх хүртэл зураг браузераас гардаггүй: `URL.createObjectURL` +
canvas-аар зөвхөн дотоод preview үүсгэдэг (`lib/photoRender.ts`).

## Back-end — `/api/order`

Захиалга нь native app-тай **яг нэг Firebase Realtime Database** руу очно:
`pmn/orders` + `pmn/worklogs` зангилаанд, `orderLogic.ts` шиг хосоороо.

### Яагаад Vercel function хэрэгтэй вэ

`RTDB_AUTH` бол Firebase-ийн *database secret* — бүрэн admin эрх. Native app-д
энэ нь bundle дотор сууж болдог (app.config.js дээр ч ингэж тайлбарласан
байдаг), гэхдээ вэб дээр bundle бол зүгээр л нэг татаж болох файл. Token-ыг
`VITE_` угтвартай нэрээр тавьбал сайт нээсэн хэн ч DevTools-оос уншаад
`pmn` доторх бүхнийг — ажилтны PIN, орлого, чат — унших, устгах боломжтой.

Тиймээс token зөвхөн серверийн орчны хувьсагчид амьдарч, browser нь
`POST /api/order` руу л хандана.

### Тохируулга

Vercel → Project → Settings → Environment Variables (`.env.example`-ийг үз):

| Хувьсагч                          | Заавал | Тайлбар                                    |
| --------------------------------- | ------ | ------------------------------------------ |
| `RTDB_AUTH`                       | ✅     | Database secret. Байхгүй бол API 503 өгнө  |
| `RTDB_URL`                        | —      | Өгөөгүй бол `…/pmn` руу бичнэ              |
| `R2_ACCOUNT_ID`                   | 🖼     | Cloudflare account id                      |
| `R2_BUCKET`                       | 🖼     | Зургийн bucket-ийн нэр                     |
| `R2_ACCESS_KEY_ID` / `_SECRET_…`  | 🖼     | R2 API token. Object Read & Write          |
| `S3_ENDPOINT` / `S3_REGION`       | —      | Өгвөл R2-ийн оронд өөр S3-нийцтэй сан руу  |
| `ADMIN_TOKEN`                     | 🖼     | `/admin` хуудсанд нэвтрэх нууц үг          |
| `BANK_NAME` / `_ACCOUNT` / `_HOLDER` | 💳  | Дансаар шилжүүлэх заавар                   |
| `QPAY_USERNAME` / `_PASSWORD` / `_INVOICE_CODE` | — | QPay QR. Байхгүй бол зөвхөн данс |
| `TELEGRAM_BOT_TOKEN` / `_CHAT_ID` | —      | Шинэ захиалгын мэдэгдэл                    |

🖼 = зураг хүлээн авахад. Байхгүй бол доорх «Сангүйгээр ажиллах» хэсгийг үз.
💳 = төлбөрийн заавар харуулахад. Байхгүй бол хэрэглэгчид «утсаар холбогдоно уу»
гэж харуулна, ажилтан гараар баталгаажуулсан хэвээр ажиллана.

### Сангүйгээр ажиллах — R2/NAS-ыг хожим залгах

**Зөвхөн `RTDB_AUTH` заавал.** Объект сан (`R2_*`) тохируулаагүй байсан ч вэб
бүрэн ажиллана:

| Юу болох вэ | Тайлбар |
| --- | --- |
| `/api/upload` | `503` буцаана |
| Клиент | `ServiceUnavailableError` барьж аваад захиалгыг **үргэлжлүүлнэ** |
| `/api/order` | `photos: 'unavailable'` гэж хариулж, захиалгыг Firebase рүү хэвийн бичнэ |
| Хэрэглэгч | «Зураг хүлээн авах систем түр ажиллахгүй байна. Ажилтан залгаж авна» гэсэн мессеж |
| Төлбөр | Дансны заавар ҮРГЭЛЖ харагдана (санаас хамаардаггүй). Автомат хяналт л ажиллахгүй |
| Telegram | «⚠️ N зураг ирсэн ч сан руу орсонгүй» гэж мэдэгдэнэ |

Хожим `R2_*` (эсвэл `S3_ENDPOINT`) хувьсагчдыг Vercel дээр тавиад redeploy
хийхэд л зургийн урсгал автоматаар асна — код өөрчлөх шаардлагагүй.

Энэ нь санамсаргүй унтралтад ч хамаарна: R2 хэдэн минут ажиллахгүй байлаа гэж
вэбээр захиалга авах боломж бүрэн зогсохгүй.

### Локал хөгжүүлэлт — хуурамч back-end

`npm run dev` үед Vercel function-ууд **ажиллахгүй** (тэдгээр нь зөвхөн deploy
хийсний дараа амьдардаг). Тиймээс `dev/mock-api.ts` нь `/api/*`-ыг локал дээр
дуурайдаг Vite plugin — бодит API-тай яг ижил хэлбэрийн хариу өгнө:

- `/api/upload` → хуурамч presigned URL (файл санах ойд хадгалагдана)
- `/api/order` → захиалгын дугаар, дансны заавар, хянах түлхүүр
- `/api/payment` → `pending` → `paid` (20 секундын дараа автоматаар)
- `/api/admin` → жагсаалт. **Ямар ч нууц үг тохирно.** Төлбөрийн түгжээ нь
  бодит API-тай ижил ажиллана — төлөөгүй захиалганд линк буцаадаггүй

```bash
npm run dev                    # төлбөр 20 секундын дараа автоматаар орно
MOCK_AUTOPAY_MS=0 npm run dev  # зөвхөн /admin дээрээс гараар баталгаажуулна
```

`apply: 'serve'` тул үйлдвэрлэлийн build-д ОРОХГҮЙ. `test/mock-api.test.ts` нь
хуурамч back-end бодит API-ийн гэрээг зөрчөөгүйг шалгана.

### App дээр хаана харагдах вэ

**Захиалга** таб (manager / ipad эрхтэй хүнд; worker-т энэ таб байхгүй).
`OrdersScreen` нь `orders` биш **`worklogs`**-ыг рендэрлэдэг — бид хоёуланд нь
бичдэг тул өдрийн касс (`orders`) болон самбар (`worklogs`) хоёулаа таарна.

Хоёр нарийн зүйл дээр анхаарсан:

- **Огноо Улаанбаатарын цагаар.** Vercel UTC-ээр явдаг тул серверийн локал
  огноог авбал өглөөний 00:00–08:00-д ирсэн захиалга өмнөх өдрөөр бичигдэж,
  `visibleWorkLogs`-ийн `date === today` шүүлтүүрээс унаж, самбарт огт
  харагдахгүй байх байсан.
- **`no` дараалал.** `newestFirst` эхлээд `no`-гоор эрэмбэлдэг тул дугааргүй
  мөр 0 болж жагсаалтын доод талд ордог. Function өнөөдрийн worklog-ийг
  индексжсэн асуултаар тоолж дугаарыг үргэлжлүүлдэг.

Мэдэгдэх хугацаа: `DataContext` 30 секунд тутам татдаг (`SYNC_INTERVAL_MS`),
тиймээс шинэ захиалга ~30 секундын дотор гарч ирнэ. Апп-ын бичилтүүд бүгд
record-level PUT (`writeChild`) учир бүтэн коллекцийг дарж вэб захиалгыг
устгах эрсдэлгүй.

### Function юу хийдэг вэ

- **Үнийг сервер дээр дахин тооцно.** Клиентийн явуулсан `unitPrice`-ыг
  зөвхөн тохиролцооны категорид (`Медаль & Цом`, `Хувцас хэвлэл`), хязгаарын
  дотор байвал л хүлээж авна. Эс тэгвээс 500₮-ийн ажлыг 1₮ болгож захиалж болно.
- **Нэг атомик multi-path PATCH.** Order, WorkLog хоёрыг тусад нь PUT хийвэл
  эхнийх нь орж, хоёр дахь нь унаж, орлого чимээгүй алдагдах эрсдэлтэй.
- **id давхцлаас сэргийлнэ** (`utils/id.ts`-ийн `nextId` логик) — id нь Firebase
  хүүхэд зам учир давхцвал нэг бичлэг нөгөөгөө дарна.
- Хүргэлт/НӨАТ-ыг зөвхөн эхний worklog дээр тэмдэглэнэ (тайланд давхар тоологдохгүй).
- IP-д суурилсан хөнгөн rate limit. Edge instance бүр өөрийн санах ойтой тул
  энэ нь баталгаа биш — жинхэнэ хэрэгцээ гарвал Upstash Redis / Vercel Firewall.

`npm test` нь 50 тест ажиллуулна: үнийн тооцоо, баталгаажуулалт, Firebase
rules-ийн `.validate` шаардлагууд, SigV4 гарын үсэг, ZIP-ийн CRC, мөн
handler-ийн бүтэн зам (хуурамч Firebase сервер дээр).

## Зураг хүлээн авах — Cloudflare R2

Гол зорилго: хэрэглэгч зургаа вэб дээр оруулна, ажилтан татаж аваад зургийн
машинд өгнө. Зураг Firebase рүү ОГТ ордоггүй — R2 (S3-тэй нийцтэй) санд очно.

### Урсгал

```
Браузер                     Vercel edge                  Cloudflare R2
   │ 1. canvas: 300dpi хэвлэлийн JPEG
   │ 2. POST /api/upload  ──────────►  presigned PUT URL үүсгэнэ ──►
   │ 3. PUT зураг ─────────────────────────────────────────────────► uploads/…
   │ 4. POST /api/order   ──────────►  Firebase: orders + worklogs
   │                                   R2:       manifests/….json
Ажилтан
   │ 5. GET /api/admin    ──────────►  manifest унших + presigned GET
   │ 6. ZIP татаж авна ◄──────────────────────────────────────────── uploads/…
```

**Файлыг сервер дундуур оруулдаггүй.** Vercel-ийн хүсэлтийн бие 4.5MB-аар
хязгаарлагдсан бөгөөд утсаар авсан нэг зураг л ихэвчлэн үүнээс том. Сервер
зөвхөн 20 минут амьдардаг presigned URL үүсгэж, браузер R2 руу шууд PUT хийнэ.

**Түлхүүрийг зөвхөн сервер тодорхойлно.** `uploads/<огноо>/<uploadId>/01-print.jpg`.
Клиентээс ирсэн замд итгэвэл дурын хүн бусдын зургийг дарж бичих боломжтой.
`/api/order` дээр түлхүүр бүр тухайн `uploadId`-ийн угтвартай эсэхийг шалгана —
эс тэгвээс хэн ч өөр захиалгын зургийг өөрийн manifest-даа оруулж татах байсан.

**Зураг бүрээс хоёр файл гарна:** `print` (сонгосон хэмжээний харьцаагаар
тайрсан, засвар тусгасан, 300dpi — шууд хэвлэнэ) ба `original` (эх файл —
тайралт буруу байвал эсвэл өөр хэмжээгээр дахин хэвлэхэд).

**Индекс нь R2 дотроо.** `manifests/<огноо>/<захиалгын дугаар>-<uploadId>.json`
дотор хэрэглэгчийн мэдээлэл, мөрүүд, файлын жагсаалт бүгд байна. Firebase-ийн
`database.rules.json` нь native app-ын мэдэлд байдаг тул шинэ зангилаа нэмэх нь
rules-ээс татгалзах эрсдэлтэй — оронд нь зураг ба индексийг нэг газар барив.
Firebase рүү зөвхөн worklog-ийн `note` дээр `🖼 N зураг вэбээр ирсэн` гэж бичнэ.

### R2 bucket тохируулах

1. Cloudflare → R2 → **Create bucket** (жишээ нь `printmn-photos`, байршил APAC).
2. **CORS policy** нэмнэ — эс тэгвээс браузерын PUT-ыг хөтөч блоклоно:

   ```json
   [
     {
       "AllowedOrigins": ["https://printmn.mn", "http://localhost:5173"],
       "AllowedMethods": ["PUT", "GET"],
       "AllowedHeaders": ["content-type"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

3. **Manage API tokens** → Object Read & Write, зөвхөн энэ bucket. Гарсан
   `Access Key ID` / `Secret Access Key`-г Vercel-д тавина.
4. Bucket-ыг **нийтэд нээхгүй**. Бүх хандалт presigned URL-ээр явна.
5. Санамсаргүй өсөлтөөс сэргийлж **lifecycle rule** нэмэхийг зөвлөнө:
   `uploads/` угтвар — 90 хоногийн дараа устгах.

### Өөр сан руу шилжих (NAS, MinIO, B2, S3)

`api/_r2.ts` нь ердийн SigV4 гарын үсэг бичдэг тул **дурын S3-нийцтэй сан**
дээр ажиллана. Код өөрчлөх шаардлагагүй — зөвхөн орчны хувьсагч:

```
S3_ENDPOINT=https://s3.printmn.mn:9000
S3_REGION=us-east-1
R2_BUCKET=photos
R2_ACCESS_KEY_ID=…
R2_SECRET_ACCESS_KEY=…
```

Дэлгүүрийн NAS дээр MinIO (Docker) ажиллуулбал зураг байрандаа очно. Гэхдээ
NAS-ыг интернэтэд гаргах нь тогтмол IP, HTTPS сертификат, урсгал хамгаалалт
шаарддаг бөгөөд дэлгүүрийн интернэт эсвэл цахилгаан унахад вэбийн зураг
хүлээн авах хэсэг бүхэлдээ зогсоно.

**Илүү аюулгүй хослол:** зураг R2 руу очиж, NAS нь R2-оос **татаж авч**
архивлана (`rclone sync` эсвэл Synology Cloud Sync, 10 минут тутам). Ингэхэд
ажилтан NAS дээрх дотоод хавтаснаас шууд хэвлэнэ, вэб нь дэлгүүрийн сүлжээнээс
хамаарахгүй, R2 дээрх хуулбарыг 30–90 хоногийн дараа автоматаар устгана.

```bash
# NAS дээрх cron — 10 минут тутам
rclone sync r2:printmn-photos/uploads /volume1/photo/web-orders \
  --create-empty-src-dirs --log-file=/volume1/logs/rclone.log
```

## Төлбөр — зураг төлбөр орсны дараа нээгдэнэ

**Дүрэм: төлбөр баталгаажтал ажилтан зургийг харах ч, татах ч боломжгүй.**

Файл нь захиалга илгээмэгц R2 руу шууд байршдаг — тэгэхгүй бол хэрэглэгч банкны
апп руу шилжих үед браузер хаагдвал зураг алдагдана. Харин **түгжээ нь линк
олгох үе шат дээр** байдаг: `/api/admin` төлөөгүй захиалганд presigned URL ОГТ
үүсгэдэггүй. Интерфейс дээр товч идэвхгүй болгох нь хамгаалалт биш — DevTools
нээсэн хэн ч тойрч гарна.

### Хоёр зам

| Зам | Тохиргоо | Баталгаажилт |
| --- | --- | --- |
| Данс руу шилжүүлэг | `BANK_NAME`, `BANK_ACCOUNT`, `BANK_HOLDER` | Ажилтан `/admin` дээр «✓ Төлбөр орсон» дарна |
| QPay (QR + банкны апп) | `QPAY_USERNAME`, `QPAY_PASSWORD`, `QPAY_INVOICE_CODE` | Автомат — QPay callback |

Хоёуланг зэрэг асааж болно: хэрэглэгч QR уншуулах эсвэл данс руу шилжүүлэхээ
өөрөө сонгоно. Аль нь ч тохируулаагүй бол утсаар холбогдох заавар гарна.

### QPay-ийн урсгал

```
/api/order  →  POST /v2/auth/token  →  POST /v2/invoice
                                            ↓  QR + deeplink
                                       хэрэглэгч төлнө
                                            ↓
QPay → /api/qpay-callback?order=…&date=…&u=…&payment_id=…
                                            ↓
                          POST /v2/payment/check  ← ЗААВАЛ
                                            ↓
                              manifest.payment.status = 'paid'
```

⚠️ **`payment/check`-ийг алгасаж болохгүй.** Callback бол нийтэд нээлттэй HTTP
хаяг — хэн ч дуудаж «төлөгдлөө» гэж бичүүлэх боломжтой. Зөвхөн QPay-ээс өөрөөс
нь асууж баталгаажуулсан үед л төлбөрийг хүлээн зөвшөөрнө. Давхар мэдэгдэл
ирвэл юу ч өөрчлөгдөхгүй (аль хэдийн төлөгдсөн manifest-ыг дахин бичихгүй).

Хэрэглэгчийн талд `/api/payment` нь 5 секунд тутам төлөв асууна — банкны
аппаасаа буцаж ирмэгц дэлгэц өөрөө «Төлбөр баталгаажлаа» болно. Нэвтрэлт нь
`uploadId` (16 тэмдэгт санамсаргүй), хариунд хувийн мэдээлэл ОГТ ордоггүй.
QPay «cron-оор байнга шалгахыг хориглоно» гэсэн тул сервер нэхэмжлэл бүрийг
20 секундэд нэгээс олон удаа шалгадаггүй.

### Telegram мэдэгдэл

`TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` тавибал **хоёр** агшинд мэдэгдэнэ:

| Хэзээ | Мессеж |
| --- | --- |
| Захиалга ирэхэд | `🌐 Вэбээс шинэ захиалга! … 🖼 3 зураг — ⏳ төлбөр хүлээгдэж байна` |
| Төлбөр орсонд | `✅ Төлбөр орлоо! … 🖼 3 зураг татахад бэлэн — /admin` |

Хоёр дахь нь **чухал**: «төлбөр эхэлж» гэсэн дүрэмтэй болсон учир зураг яг энэ
мөчид түгжээгээ тайлдаг. Мэдэгдэлгүй бол ажилтан `/admin`-ыг байнга сэргээж
хараад суух хэрэгтэй болно. QPay callback, `/api/payment` шалгалт, `/admin`
дээрх гараар баталгаажуулалт — гурвуулаа мэдэгдэл илгээнэ.

**Тохируулах:** BotFather-аас бот үүсгэж token авах → ботоо дэлгүүрийн групп рүү
нэмэх → групп рүү мессеж бичээд `https://api.telegram.org/bot<TOKEN>/getUpdates`
дуудаж `chat.id` авах (групп бол хасах тоо).

### Захиалгын төлөв — `/zakhialga/<дугаар>?d=…&u=…`

Баталгаажуулалт нь түр зуурын дэлгэц биш, **буцаж орж болдог хаяг**. Ингэснээр
хуудсаа сэргээхэд захиалга алдагдахгүй, төлбөрөө маргааш төлж болно, линкээ
хуваалцаж өөр хүнээр төлүүлж ч болно.

Хаягийг мэдэх нь хангалтгүй: `u` (uploadId, 16 тэмдэгт санамсаргүй) байхгүй бол
сервер өгөгдөл буцаадаггүй тул дугаарыг таасан ч өөр хүний захиалгыг харах
боломжгүй. Хариунд и-мэйл, тайлбар зэрэг илүү мэдээлэл ОРОХГҮЙ.

Баримт нь `localStorage`-д 14 хоног хадгалагдаж, нүүр болон `/hevlel` дээр
«Сүүлийн захиалга» мөр болж гарна — хэрэглэгч линкээ хаясан ч олно.

### Давхар захиалгаас хамгаалах

Клиент илгээх оролдлого бүрт `requestId` үүсгэнэ; сүлжээ унаж дахин илгээвэл
ижил утга явна. Сервер тухайн id-г 10 минут санаж, давтагдсан хүсэлтэд **шинэ
захиалга үүсгэхгүй** — өмнөх хариугаа буцаана.

Үүнгүй бол сүлжээ удаашрахад дахин дарсан хэрэглэгч Firebase-д хоёр захиалга
бичүүлж, өдрийн касс болон ажлын самбар давхардаж, ажилтан хоёр удаа хэвлэх
эрсдэлтэй. (Edge instance бүр өөрийн санах ойтой тул бүрэн баталгаа биш —
жинхэнэ баталгаа хэрэгтэй бол Upstash Redis.)

### `/admin` — ажилтны хуудас

`ADMIN_TOKEN` нууц үгээр нэвтэрнэ (`sessionStorage`-д хадгална, таб хаагдмагц
устана). Захиалга бүрийн зургийг харах, нэг бүрчлэн эсвэл **ZIP-ээр** татах,
"хэвлэсэн" гэж тэмдэглэх боломжтой.

Төлбөр хүлээгдэж буй захиалга **🔒 түгжээтэй** харагдана: зургийн тоо, дүн,
захиалагчийн мэдээлэл харагдах ч зураг өөрөө биш. «✓ Төлбөр орсон» дарахад
сервер шинэ линкүүдийг тэр дор нь буцаана — хуудсаа дахин ачаалах шаардлагагүй.

ZIP-ийг браузер дотор `src/lib/zip.ts` (шахалтгүй, хамааралгүй ~120 мөр)
угсарна. Хөтөч 10-аас олон файлыг дараалан татахыг хориглодог тул 20 зурагтай
захиалганд нэг бүрчлэн татах нь ажиллахгүй.

## Гүйцэтгэл

Зорилтот хэрэглэгч бол **гар утас, 4G, дунджаас доогуур төхөөрөмж**. Тиймээс
байт хэмнэхээс илүү *үндсэн урсгалыг чөлөөтэй байлгах* тал дээр анхаарсан.

**Замын түвшний хуваалт.** Нүүр хуудсанд каталог (17KB), захиалгын маягт,
зургийн код, ажилтны хуудас хэрэггүй. `React.lazy` ашиглан анхны JS-ийг
~92KB → ~62KB gzip болгосон. Салангид байснаас үүсэх цорын ганц сул тал —
товч дарахад хүлээх — `requestIdleCallback` дээрх урьдчилсан татаж авалтаар
арилсан (`usePrefetchMainRoutes`).

**Гуравдагч сан тусдаа chunk-д.** React, react-router бараг өөрчлөгддөггүй тул
`vendor` файлд гаргасан — бидний код шинэчлэгдэх бүрт хэрэглэгч дахин татахгүй.

**Зургийг үндсэн урсгал дээр задлахгүй.** Утасны 12MP зураг ~50MB битмап
үүсгэдэг. `<img src=…>` бол үүнийг үндсэн урсгал дээр задалж интерфейсийг
царцаадаг. Оронд нь `createImageBitmap` (урсгалаас гадуур) ашиглаж, ажил
дуусмагц `close()`-оор санах ойг нэн даруй чөлөөлнө.

**Эх файл DOM-д хэзээ ч ордоггүй.** Зураг сонгосон даруйд 640px-ийн жижиг
хувилбар үүсгээд интерфейст зөвхөн түүнийг харуулна. Сагсанд 20 зураг байсан ч
санах ойд хэдхэн MB эзэлнэ (`File` заагч + жижиг preview).

**Захиалга илгээх үе хоёр үе шаттай.** `prepare` (хэвлэлийн JPEG бэлдэх) ба
`upload` (сүлжээ) — хоёулаа явцын мөрөнд харагдана. Зураг бүрийн дараа
хөтөчид зурах завсар өгдөг тул олон зурагтай захиалгад ч интерфейс царцахгүй.

**`vercel.json`** нь SPA-гийн гүн линкийг (`/hevlel` дээр F5 дарах) зөв
шийдэж, `/assets/*`-д нэг жилийн `immutable` кэш, `/admin`-д `noindex` тавьдаг.

**Тасарсан байршуулалтыг дахин оролдоно.** Гар утасны сүлжээ богино хугацаанд
тасрах нь энгийн үзэгдэл. Файл бүрийг backoff-той 3 удаа оролдоно; `4xx`
(гарын үсэг хугацаа дууссан) дээр давтахгүй — утгагүй. Үүнгүй бол 20 зурагтай
захиалга 19 дэх дээрээ унаж, хэрэглэгч бүхнийг эхнээс нь давтах хэрэгтэй болно.

**Маягтын жижиг зүйлс.** `autocomplete`/`inputmode`/`type="tel"` — утас өөрөө
бөглөж, зөв гар гаргана. Утасны талбар зөвхөн цифр авна (хэрэглэгч зай, зураас
бичсэн ч шалгалтад унахгүй). Алдаатай илгээвэл эхний алдаатай талбар руу
автоматаар гүйлгэж фокус өгнө — утсан дээр алдааны текст дэлгэцээс гадуур
үлдэж, хэрэглэгч эргэлзэх нь түгээмэл. Зураг илгээж байх үед хуудас хаахаас
сэрэмжлүүлнэ.

## Анхаарах

- **`@utility` vs `@layer components`** — Tailwind v4-д зөвхөн `@utility`-аар
  тодорхойлсон класс дээр `@apply` хийж болно. `.btn-accent { @apply btn … }`
  ажиллаж байгаа шалтгаан нь энэ.
- **Хэмжээ таних** — `lib/photoSize.ts` нь үйлчилгээний **нэрнээс** хэмжээг
  уншдаг. Каталогт шинэ мөр нэмэхдээ `10*15` эсвэл `А4` хэлбэрийг хадгална,
  эс бөгөөс 10×15 руу унана (`FALLBACK_SIZE`).
- **Зураг браузераас гардаггүй** — `PhotoEditor` нь object URL + canvas ашиглан
  зөвхөн дотоод preview үүсгэнэ. Файлыг сервер рүү илгээх бол `api/order.ts`
  дээр тусдаа upload зам нэмэх шаардлагатай.
- **Каталог хатуу бичигдсэн** — `src/data/catalog.ts` нь seed өгөгдлийн хуулбар.
  App дотор үнэ өөрчлөгдвөл энд тусахгүй. Хэрэв синк хэрэгтэй бол function
  дотроос `pmn/services`-ыг уншиж, кэшлэх нь зөв алхам.
