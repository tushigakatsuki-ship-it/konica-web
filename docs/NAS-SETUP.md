# NAS холболт — вэбийн зургийг дэлгүүрийн NAS руу автоматаар татах

> **Эхлээд суулгаж байна уу?** → [`SETUP.md`](SETUP.md) нь Cloudflare-аас NAS
> хүртэлх бүх алхмыг дараалуулсан жагсаалт. Энэ баримт нь NAS-ын талын
> ДЭЛГЭРЭНГҮЙ тайлбар — яагаад ийм архитектур сонгосон, юу нь хэрхэн
> хамгаалагдсаныг өгүүлнэ.

Энэ баримт нь `konica-web`-ээр ирсэн **төлөгдсөн** захиалгын зургийг дэлгүүрийн
NAS дээрх хавтас руу 10 минут тутам автоматаар татаж, ажилтан шууд хэвлэх
боломжийг гаргана.

---

## 1. Ямар архитектур сонгосон, яагаад

```
  Хэрэглэгчийн браузер
        │  300dpi JPEG
        ▼
  Vercel (/api/upload → presigned PUT)
        │
        ▼
  Cloudflare R2  ──────────────  uploads/…  +  manifests/…
        ▲                                   │
        │ presigned GET (зөвхөн ТӨЛӨГДСӨН)  │
        │                                   │
  Vercel (/api/admin)  ◄───────────────────┘
        ▲
        │  HTTPS, гадагш чиглэсэн хүсэлт, x-admin-token
        │
  ┌─────┴──────────────────────────────────┐
  │  NAS — nas-sync.py (cron, 10 мин тутам) │
  │  /volume1/photo/web-orders/…            │
  └─────┬──────────────────────────────────┘
        ▼
  Ажилтан дотоод сүлжээнээс шууд хэвлэнэ
```

**Гол шийдвэр: NAS нь ТАТДАГ (pull), интернэтэд ГАРДАГГҮЙ.**

Ингэснээр:

| | Энэ шийдэл | NAS-ыг MinIO болгож интернэтэд гаргах |
| --- | --- | --- |
| Тогтмол IP хэрэгтэй юу | ❌ Үгүй | ✅ Тийм |
| HTTPS сертификат | ❌ Үгүй | ✅ Тийм (сунгаж байх) |
| Router дээр порт нээх | ❌ Үгүй | ✅ Тийм |
| Дэлгүүрийн интернэт унахад | Вэб хэвийн, NAS дараа нь гүйцээнэ | **Вэбийн зураг хүлээн авах бүхэлдээ зогсоно** |
| Дэлгүүрийн цахилгаан унахад | Вэб хэвийн | **Вэб зураг авахаа болино** |
| NAS хакердагдвал | Зөвхөн ADMIN_TOKEN алдагдана | Объект сангийн бүрэн эрх алдагдана |

### Яагаад `/api/admin`-аар татдаг вэ, R2 руу шууд `rclone sync` хийдэггүй вэ

Энэ бол хамгийн чухал цэг. Төслийн дүрэм нь:

> **Төлбөр баталгаажтал ажилтан зургийг харах ч, татах ч боломжгүй.**

Файл нь захиалга илгээмэгц R2 руу шууд байршдаг (банкны апп руу шилжих үед
браузер хаагдвал зураг алдагдахгүйн тулд). Түгжээ нь **линк олгох үе шат дээр**
байдаг — `api/admin.ts` дотор:

```ts
const paid = isPaid(order.payment);
url: paid ? await store.fileUrl(file.key) : null
```

Хэрэв NAS дээр `rclone sync r2:bucket/uploads …` гэж бичвэл энэ түгжээг
**бүрэн тойрч гарна** — төлөөгүй хүний зураг ажилтны хавтсанд шууд ирнэ.
Тиймээс `nas-sync.py` нь R2 руу огт хандахгүй, зөвхөн `/api/admin` руу
хандаж, сервер өөрөө шүүсэн линкийг л татна.

Дагалдах ашиг: **NAS дээр R2-ийн түлхүүр хадгалахгүй.** Зөвхөн `ADMIN_TOKEN`.

## 2. Урьдчилсан шаардлага

| Юу | Тайлбар |
| --- | --- |
| NAS | Synology (DSM 7+), QNAP (QTS 5+), эсвэл Linux-т суурилсан дурын NAS |
| Python 3.8+ | Synology: Package Center → **Python 3**. QNAP: App Center → **Python3** |
| Интернэт холболт | Зөвхөн гадагш. Порт нээх, IP тогтоох шаардлагагүй |
| Vercel дээр `ADMIN_TOKEN` | Аль хэдийн тохируулсан байх ёстой (`/api/admin` үүнгүйгээр 503 өгнө) |
| Vercel дээр `R2_*` | Аль хэдийн тохируулсан байх ёстой (эс тэгвээс зураг огт хадгалагдахгүй) |

Сервер тал нь энэ урсгалыг дэмжихээр бэлдэгдсэн:

| Endpoint | Юунд |
| --- | --- |
| `GET /api/health` | Тохиргоо бүрэн эсэх — `--check` үүнийг уншина |
| `GET /api/admin?state=pending-sync` | Төлөгдсөн БӨГӨӨД татагдаагүй захиалгууд |
| `GET /api/admin?ref=…` | Ганц захиалга (`--resync`) |
| `POST /api/admin {action:'synced'}` | «NAS татаж дууслаа» гэж тэмдэглэх |

## 3. Synology дээр суулгах

### 3.1. Хавтас бэлдэх

**File Station** дээр дараах бүтцийг үүсгэнэ (эсвэл SSH-ээр `mkdir -p`):

```
/volume1/photo/web-orders/
/volume1/photo/web-orders/_config/
```

`photo` shared folder байхгүй бол Control Panel → Shared Folder → Create.

### 3.2. Python 3 суулгах

Package Center → хайх `Python 3` → **Install**. Дараа нь SSH-ээр шалгана:

```bash
python3 --version     # 3.8 ба түүнээс дээш байх ёстой
```

SSH идэвхжүүлээгүй бол: Control Panel → Terminal & SNMP → Enable SSH service.

### 3.3. Скриптийг байрлуулах

`nas-sync.py` файлыг `/volume1/photo/web-orders/_config/nas-sync.py` руу хуулна
(File Station-аар drag & drop бас болно). Дараа нь SSH-ээр:

```bash
chmod +x /volume1/photo/web-orders/_config/nas-sync.py
```

### 3.4. Тохиргооны файл

`/volume1/photo/web-orders/_config/nas-sync.env` үүсгэж дараахыг бичнэ:

```bash
# Вэбийн хаяг — сүүлийн налуу зураасгүй
KONICA_API_BASE=https://printmn.mn

# Vercel → Settings → Environment Variables → ADMIN_TOKEN дахь ЯГ тэр утга
KONICA_ADMIN_TOKEN=PASTE_YOUR_TOKEN_HERE

# Зураг очих газар
KONICA_DEST=/volume1/photo/web-orders

# Сүүлийн хэдэн өдрийг шалгах. 7 хангалттай — өдөрт олон удаа ажилладаг.
KONICA_DAYS=7
```

> ⚠️ `PASTE_YOUR_TOKEN_HERE`-ийг ЖИНХЭНЭ утгаар нь солино. Токен нь зөвхөн
> латин үсэг, тоо байх ёстой — кирилл үсэг HTTP толгойд огт багтдаггүй.
> (Солихоо мартвал скрипт тэрийг барьж, ойлгомжтой алдаа өгнө.)

**Энэ файлыг заавал хамгаална** — доторх токен нь бүх захиалгын зургийг татах
эрхтэй:

```bash
chmod 600 /volume1/photo/web-orders/_config/nas-sync.env
chown root:root /volume1/photo/web-orders/_config/nas-sync.env
```

### 3.5. Туршиж үзэх

Эхлээд **юу ч татахгүй** шалгалт — тохиргоо, сервер, токен, дискний бичих эрх
дөрвүүлэнг нэг дор:

```bash
cd /volume1/photo/web-orders/_config
python3 nas-sync.py --check
```

```
✓ storage  : «printmn-photos» бакет, …
✓ admin    : ADMIN_TOKEN бөглөгдсөн — NAS холбогдох боломжтой.
✓ payment  : Дансны шилжүүлэг бэлэн …
✗ notify   : Telegram мэдэгдэл унтарсан (заавал биш) …

✓ Токен:   зөв — 2 татах захиалга хүлээгдэж байна (сүүлийн 1 хоногт нийт 5).
✓ Хавтас:  бичих эрхтэй — /volume1/photo/web-orders
```

Ямар нэг мөр `✗` бол Vercel-ийн тал дутуу — [`SETUP.md`](SETUP.md)-ийн Алхам 7,
8-ыг үз. Токен буруу бол `--check` шууд хэлнэ.

Дараа нь юу татагдахыг харна:

```bash
python3 nas-sync.py --dry-run
```

Хүлээгдэх хариу:

```
[2026-08-18 14:20:01] Эхэллээ — сүүлийн 7 өдөр, https://printmn.mn
[2026-08-18 14:20:02] 5 захиалга ирлээ — 2 шинэ төлөгдсөн, 3 төлөгдөөгүй (алгасна)
[2026-08-18 14:20:02]   PMN-260818-4821: 6 файл татах байсан → …
[2026-08-18 14:20:02] Туршилтын горим — 2 захиалга татагдах байсан.
```

Зөв бол `--dry-run`-гүйгээр нэг удаа гараар ажиллуулж, файл ирснийг шалгана:

```bash
python3 nas-sync.py
```

### 3.6. Автоматжуулах (Task Scheduler)

Control Panel → **Task Scheduler** → Create → **Scheduled Task** → **User-defined script**

| Талбар | Утга |
| --- | --- |
| Task | `Вэбийн зураг татах` |
| User | `root` |
| Schedule | Daily, **Repeat every 10 minutes**, 00:00–23:59 |
| Run command | `/usr/local/bin/python3 /volume1/photo/web-orders/_config/nas-sync.py` |

> Python-ы зам өөр байж болно. `which python3` эсвэл
> `readlink -f $(which python3)` гэж шалгаад тэр замыг тавина.

**Notification** таб дээр «Send run details by email» → **only when the script
terminates abnormally** гэж тохируулбал алдаа гарсан үед л мэйл ирнэ.

## 4. QNAP дээр суулгах

Ижил зарчим, зөвхөн зам болон хуваарь өөр:

```bash
# Хавтас
mkdir -p /share/photo/web-orders/_config

# Тохиргоо — KONICA_DEST=/share/photo/web-orders гэж бичнэ
vi /share/photo/web-orders/_config/nas-sync.env
chmod 600 /share/photo/web-orders/_config/nas-sync.env

# crontab
echo '*/10 * * * * /opt/bin/python3 /share/photo/web-orders/_config/nas-sync.py >/dev/null 2>&1' >> /etc/config/crontab
crontab /etc/config/crontab && /etc/init.d/crond.sh restart
```

> QNAP дээр `/etc/config/crontab` руу бичих ёстой — `crontab -e` нь firmware
> шинэчлэгдэхэд арчигдана.

## 6. Скрипт хэрхэн аюулгүй ажилладаг вэ

| Асуудал | Хэрхэн шийдсэн |
| --- | --- |
| Төлөгдөөгүй зураг ирэх | Сервер линк өгдөггүй — физикээр татах боломжгүй |
| Cron давхцаж ажиллах | `_state/sync.lock` — өмнөх нь дуустал алгасна (1 цагийн дараа хуучирсан гэж үзнэ) |
| Дунд нь тасрах → хагас зураг | `.part-*` түр файл руу татаж, БҮРЭН болсны дараа нэрлэнэ |
| Нэг файлыг дахин дахин татах | `synced.json` + файлын хэмжээ таарч байвал алгасна |
| NAS дахин суулгасны дараа БҮГД дахин татагдах | Сервер дээрх `syncedAt` барина — `synced.json` алдагдсан ч давхардахгүй |
| Cron бүрд 7 хоногийн бүх файлд линк үүсэх | `?state=pending-sync` — сервер өөрөө шүүнэ, ихэвчлэн хоосон жагсаалт ирнэ |
| Сүлжээ түр тасрах | 3 удаа дахин оролдоно (5с → 10с → 20с) |
| Токен буруу | Шууд зогсоод тодорхой мессеж бичнэ, дахин оролдохгүй |
| Хэсэгчлэн амжилтгүй болох | Тухайн захиалгыг «дууссан» гэж тэмдэглэхгүй — дараагийн ажиллалт гүйцээнэ |

Гарах кодууд: `0` = зүгээр, `1` = алдаа гарсан, `2` = тохиргоо дутуу.

## 7. Түгээмэл асуудал

**«Тохиргоо дутуу байна: KONICA_ADMIN_TOKEN»**
`nas-sync.env` олдоогүй эсвэл мөр буруу бичигдсэн. Скрипт `--config` замыг
өгөөгүй бол `/volume1/photo/web-orders/_config/nas-sync.env`,
`/share/photo/web-orders/_config/nas-sync.env`, `~/.config/konica/nas-sync.env`
гурвыг л хайна. Өөр газар байвал `--config /зам/файл` гэж шууд заана.

**«ADMIN_TOKEN буруу байна (HTTP 401)»**
Vercel дээрх `ADMIN_TOKEN`-ыг сольсон бол `nas-sync.env`-ээ мөн шинэчилнэ.
Хоосон зай эсвэл хашилт орсон эсэхийг шалгана.

**«Сервер дээр ADMIN_TOKEN … тохируулаагүй байна (HTTP 503)»**
Энэ бол NAS-ын биш, Vercel-ийн тал. Settings → Environment Variables дээр
`ADMIN_TOKEN` болон `R2_*` бөглөөд **redeploy** хийнэ.

**Зураг ирэхгүй, «N төлөгдөөгүй (алгасна)» гэж бичээд байна**
Энэ бол зөв ажиллаж байгаа хэрэг. Дансаар төлсөн захиалгыг ажилтан гараар
баталгаажуулах ёстой (апп дээр эсвэл `POST /api/admin {action:'pay'}`).
Баталгаажсаны дараа дараагийн ажиллалтад зураг ирнэ.

**Нэг захиалгыг дахин татах**
```bash
python3 nas-sync.py --resync PMN-260818-4821
```

**7 хоногоос хуучин захиалга дутуу байна**
```bash
python3 nas-sync.py --days 31        # дээд тал нь 31
```

## 8. Шударга анхааруулга

**1. NAS одоо архивын үүрэгтэй болно.** R2 дээр `uploads/` угтварт 90 хоногийн
lifecycle rule зөвлөсөн байдаг. Тэр хугацаа өнгөрөхөд R2 дээрх хуулбар устана —
NAS дээрх нь **цорын ганц хуулбар** болно.

**RAID бол нөөцлөлт биш.** NAS-аа гал, хулгай, ransomware-ээс хамгаалахын тулд
Hyper Backup (Synology) эсвэл HBS3 (QNAP)-аар өөр газар руу нөөцөлнө. Хэрэв
үүнийг хийхгүй бол R2 дээрх lifecycle rule-аа 90 хоногоос уртасгах, эсвэл огт
тавихгүй байхыг зөвлөнө — үүлэн хуулбар байсаар байсан нь дээр.

**2. Энэ скрипт файл УСТГАДАГГҮЙ.** Хавтас байнга өснө. Улирал бүр гараар
шалгаж, хуучин сарын хавтсыг архив диск рүү зөөнө. Автоматаар устгадаг болгох
нь техникээр амархан ч, хэрэглэгчийн зургийг програм өөрөө устгах эрсдэлийг
би санаатайгаар аваагүй.

**3. `--days 7` цонх.** 7 хоногоос хойш баталгаажсан төлбөрийг скрипт олохгүй.
Дансаар удаан төлдөг үйлчлүүлэгч байвал `KONICA_DAYS=31` болгоно — сүлжээний
ачаалал мэдэгдэхүйц нэмэгдэхгүй, учир нь аль хэдийн татсан файлыг алгасдаг.

**4. Токен нь бүх зургийн эрх.** `nas-sync.env` алдагдвал сүүлийн 31 хоногийн
төлөгдсөн бүх захиалгын зураг татагдах боломжтой. `chmod 600`-ыг заавал хийнэ.
Ажилтан солигдох бүрд токеноо солих нь зөв дадал (Vercel дээр солиод, NAS дээр
шинэчлээд, redeploy).

**5. Хэвлэсэн тэмдэглэгээ автоматжаагүй.** Скрипт зөвхөн ТАТДАГ. `printedAt`-ыг
ажилтны апп дээрээс тэмдэглэсэн хэвээр байна. Үүнийг автоматжуулах нь буруу —
файл татагдсан гэдэг нь хэвлэгдсэн гэсэн үг биш.

## 9. Хожим NAS-ыг үндсэн сан болгох бол

Хэрэв дараа нь дэлгүүрийн MinIO руу бүрэн шилжихээр шийдвэл код өөрчлөх
шаардлагагүй — `api/_r2.ts` нь ердийн SigV4 бичдэг тул зөвхөн Vercel дээрх
орчны хувьсагч солигдоно:

```
S3_ENDPOINT=https://s3.printmn.mn:9000
S3_REGION=us-east-1
R2_BUCKET=photos
R2_ACCESS_KEY_ID=…
R2_SECRET_ACCESS_KEY=…
```

Гэхдээ тэр үед 1-р хэсэгт бичсэн бүх сул тал (тогтмол IP, сертификат, порт,
цахилгаан/интернэтээс хамаарах) буцаж ирнэ. Миний зөвлөмж: **бүү яар.** Энэ
баримт дахь pull-загвар нь дэлгүүрийн хувьд бараг үргэлж дээр.
